## Description

The header file paths are: `"simt_api/device_atomic_functions.h"` (for interfaces other than the half, half2, bfloat16\_t, and bfloat16x2\_t types), `"simt_api/asc_fp16.h"` (for the half and half2 type interfaces), and `"simt_api/asc_bf16.h"` (for the bfloat16\_t and bfloat16x2\_t type interfaces).

Performs an atomic minimum operation on Unified Buffer (UB) or Global Memory data, that is, assigns the minimum value between the UB or Global Memory data and the specified data to the UB or Global Memory address.

## Return Value

Initial data in UB or Global Memory.

Note that due to underlying hardware constraints, the return values of the half and bfloat16_t types are inaccurate. Direct use of the return values of these types is prohibited. The half2 and bfloat16x2_t types are not subject to this restriction.

## Constraints

-   Atomic operations guarantee the atomicity of the read-modify-write process on the same address, but do not guarantee the execution order among multiple threads. For scenarios that rely on the interface return value to determine the order of threads, the result may vary with thread scheduling.
-   The performance of this interface is affected by the following factors. For the related principles, see [Atomic Operation Mechanism](atomic_operations_intro.md#atomic-operation-mechanism).
    -   Memory space: The access path of UB is shorter than that of Global Memory and usually has lower access overhead. When the data type in use supports UB (that is, int32\_t, uint32\_t, float, half, bfloat16\_t, half2, bfloat16x2\_t), it is recommended to perform atomic operations in UB first.
    -   Return value: Whether the return value is used may affect the atomic instruction generated by the compiler. The following table shows whether a better instruction can be generated for each data type when the return value is not used:

        | Data Type | Whether a Better Instruction Is Generated When the Return Value Is Not Used |
        | --- | --- |
        | int32\_t, uint32\_t, float, half, bfloat16\_t, half2, bfloat16x2\_t | Yes |
        | int64\_t, uint64\_t | No |

        When the business scenario allows, it is recommended not to use the return value.
    -   Address distribution: Global Memory atomic operations are processed through the L2 Cache. The L2 Cache uses a 512B Cache Line as the cache management unit, and each Cache Line contains four 128B sectors. Global Memory atomic operations use a 128B Sector as the processing granularity. When destination addresses are concentrated within the same Sector, processing efficiency is lower; when destination addresses are distributed across more Sectors, processing efficiency is higher. Therefore, when the business allows, it is recommended to distribute the destination addresses of atomic operations across more Sectors.

## Examples

The example scenario is as follows: multiple threads scan a latency array and use the `asc_atomic_min()` interface to write the global minimum latency to the same result address. The input parameters are described as follows:

| Name | Description |
| --- | --- |
| `latency` | Each element represents the latency value of a request. |
| `min_latency` | The minimum value result in Global Memory, initialized to a sufficiently large value before kernel startup. |
| `n` | Number of latency samples. |

The core code implementation is as follows:

-   SIMT programming scenario:

    ```cpp
    #include "simt_api/device_atomic_functions.h"

    __global__ __launch_bounds__(256) void find_min_latency(uint32_t *min_latency,
                                                           uint32_t *latency,
                                                           uint32_t n)
    {
        uint32_t idx = blockIdx.x * blockDim.x + threadIdx.x;
        if (idx >= n) {
            return;
        }

        asc_atomic_min(min_latency, latency[idx]);
    }
    ```

-   SIMD and SIMT hybrid programming scenario:

    In this scenario, address space qualifiers must be explicitly used to indicate the address space: `__gm__` indicates the Global Memory memory space, and `__ubuf__` indicates the UB memory space.

    ```cpp
    #include "simt_api/device_atomic_functions.h"

    __simt_vf__ __launch_bounds__(1024) inline void find_min_latency(__gm__ uint32_t *min_latency,
                                                                    __gm__ uint32_t *latency,
                                                                    uint32_t n)
    {
        uint32_t idx = blockIdx.x * blockDim.x + threadIdx.x;
        if (idx >= n) {
            return;
        }

        asc_atomic_min(min_latency, latency[idx]);
    }
    ```

The output result example is as follows:

```
latency: 31, 20, 45
min_latency: 20 // Indicates the minimum value obtained after all threads update concurrently.
```
