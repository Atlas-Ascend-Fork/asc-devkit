## Description

The header file paths are: `"simt_api/device_atomic_functions.h"` (for interfaces other than the half, half2, bfloat16\_t, and bfloat16x2\_t types), `"simt_api/asc_fp16.h"` (for the half and half2 type interfaces), and `"simt_api/asc_bf16.h"` (for the bfloat16\_t and bfloat16x2\_t type interfaces).

Performs an atomic maximum operation on Unified Buffer (UB) or Global Memory data, that is, assigns the maximum of the data in UB or Global Memory and the specified data to the UB or Global Memory address.

## Return Value

Initial data in UB or Global Memory.

Note that due to underlying hardware constraints, the return values of the half and bfloat16_t types are inaccurate, and directly using the return values of these types is prohibited. The half2 and bfloat16x2_t types are not subject to this restriction.

## Constraints

-   The atomic operation guarantees the atomicity of the read-modify-write process on the same address, but does not guarantee the execution order among multiple threads. In scenarios where the interface return value is used to determine the order of threads, the result may vary with thread scheduling.
-   The performance of this interface is affected by the following factors. For the related principles, see [Atomic Operation Mechanism](atomic_operations_intro.md#atomic-operation-mechanism).
    -   Memory space: The access path of UB is shorter than that of Global Memory, and usually has lower access overhead. When the data type used supports UB (that is, int32\_t, uint32\_t, float, half, bfloat16\_t, half2, bfloat16x2\_t), it is recommended to perform the atomic operation in UB first.
    -   Return value: Whether the return value is used may affect the atomic instruction generated by the compiler. The following table shows whether a better instruction can be generated for each data type when the return value is not used:

        | Data Type | Whether a better instruction is generated when the return value is not used |
        | --- | --- |
        | int32\_t, uint32\_t, float, half, bfloat16\_t, half2, bfloat16x2\_t | Yes |
        | int64\_t, uint64\_t | No |

        When the business scenario allows, it is recommended not to use the return value.
    -   Address distribution: Global Memory atomic operations are processed through the L2 Cache. The L2 Cache uses a 512B Cache Line as the cache management unit, and each Cache Line contains four 128B sectors. Global Memory atomic operations are processed at the granularity of a 128B Sector. When destination addresses are concentrated within the same Sector, processing efficiency is lower; when destination addresses are distributed across more Sectors, processing efficiency is higher. Therefore, when the business allows, it is recommended to distribute the destination addresses of atomic operations across more Sectors.

## Examples

The example scenario is as follows: multiple threads scan a score array and use the `asc_atomic_max()` interface to write the global highest score to the same result address. The input parameters are described as follows:

| Name | Description |
| --- | --- |
| `scores` | Each element represents a candidate score. |
| `max_score` | The maximum value result in Global Memory, initialized to a sufficiently small value before kernel launch. |
| `n` | Number of scores. |

The core code implementation is as follows:

-   SIMT programming scenario:

    ```cpp
    #include "simt_api/device_atomic_functions.h"

    __global__ __launch_bounds__(256) void find_max_score(uint32_t *max_score,
                                                         uint32_t *scores,
                                                         uint32_t n)
    {
        uint32_t idx = blockIdx.x * blockDim.x + threadIdx.x;
        if (idx >= n) {
            return;
        }

        asc_atomic_max(max_score, scores[idx]);
    }
    ```

-   SIMD and SIMT hybrid programming scenario:

    In this scenario, address space qualifiers must be explicitly used to indicate the address space: `__gm__` indicates the Global Memory space, and `__ubuf__` indicates the UB memory space.

    ```cpp
    #include "simt_api/device_atomic_functions.h"

    __simt_vf__ __launch_bounds__(1024) inline void find_max_score(__gm__ uint32_t *max_score,
                                                                  __gm__ uint32_t *scores,
                                                                  uint32_t n)
    {
        uint32_t idx = blockIdx.x * blockDim.x + threadIdx.x;
        if (idx >= n) {
            return;
        }

        asc_atomic_max(max_score, scores[idx]);
    }
    ```

The output example is as follows:

```
scores: 7, 12, 4, 25
max_score: 25 // Indicates the maximum value obtained after all threads update concurrently.
```
