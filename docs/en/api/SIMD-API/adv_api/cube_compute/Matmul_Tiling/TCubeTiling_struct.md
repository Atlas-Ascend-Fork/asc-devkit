# TCubeTiling Structure

<!-- md-trans-meta sourceCommit=754fb95859dead826727a591e674261c6a829a08 translatedAt=2026-10-08T13:26:14.811Z pushedAt=2026-10-26T13:25:12.282Z -->

The TCubeTiling structure contains the parameters related to the Matmul Tiling splitting algorithm. It is passed to the Matmul kernel (Kernel) side and used for the tiling, data movement, and computation processes of Matmul. For the parameter description of the TCubeTiling structure, see [Table 1](#tcubetiling-struct).

**Table 1**  TCubeTiling structure description

<a id="tcubetiling-struct"></a>

| Parameter | Data Type | Description |
| --- | --- | --- |
| usedCoreNum | int | Number of AI processor cores used. Set it based on the actual situation. Value range: [1, maximum number of AI processor cores]. The relationship between this parameter and the shape-related parameters is: usedCoreNum = (M / singleCoreM) * (N / singleCoreN). |
| M, N, Ka, Kb | int | Shape size of the raw input of cubes A, B, and C, in elements. M and Ka are the shape of the raw input of cube A, and Kb and N are the shape of the raw input of cube B.<br>Size constraints:<br><!-- npu="950" id1 -->Except for the Ascend 950PR&950DT products, <!-- end id1 -->the [intrinsicsCheck](../Matmul_Kernel/MatmulConfig.md#matmulconfig-params) parameter in MatmulConfig must be enabled in the following scenarios to complete the Matmul computation.<br>If cube A is in ND format and is not transposed, the intrinsicsCheck parameter must be enabled when Ka is greater than 65535, and M has no size limit. If it is transposed, the intrinsicsCheck parameter must be enabled when M is greater than 65535, and Ka has no size limit.<br>If cube B is in ND format and is not transposed, the intrinsicsCheck parameter must be enabled when N is greater than 65535, and Kb has no size limit. If it is transposed, the intrinsicsCheck parameter must be enabled when Kb is greater than 65535, and N has no size limit.<br><br>Alignment constraints:<br>If cube A is input in NZ format, M must be aligned to 16 elements and Ka must be aligned to C0_size. If cube B is input in NZ format, Kb must be aligned to C0_size and N must be aligned to 16 elements.<br>If cubes A and B are in ND format, there is no alignment constraint.<br><br>Note: For NZ format input, C0_size is 8 for the float data type, 16 for the half/bfloat16_t data type, 32 for the int8_t/fp8_e4m3fn_t/fp8_e5m2_t/hifloat8_t data type, and 64 for the int4b_t/fp4x2_e2m1_t/fp4x2_e1m2_t data type. |
| singleCoreM, singleCoreN, singleCoreK<a name="p11899125875617"></a> | int | Shape size of cubes A, B, and C within a single core, in elements. The value of this parameter must be greater than 0.<br><br>singleCoreK = K, and K is not split during multi-core processing. singleCoreM <= M; singleCoreN <= N.<br><br>Note: If cube A is input in NZ format, singleCoreM must be aligned to 16 elements and singleCoreK must be aligned to C0_size. If cube B is input in NZ format, singleCoreK must be aligned to C0_size and singleCoreN must be aligned to 16 elements. |
| baseM, baseN, baseK<a name="p17899165811566"></a> | int | Shape size of cubes A, B, and C involved in one cube multiplication instruction, in elements.<br><br>The shape size of cubes A, B, and C involved in one cube multiplication must be aligned according to the fractal format. | <a id="deptha1"></a>depthA1, depthB1 | int | depthA1 and depthB1 indicate the number of fully loaded basic blocks in L1 Buffer (A1) and L1 Buffer (B1), respectively. depthA1 is the number of fully loaded baseM * baseK blocks in L1 Buffer (A1), and depthB1 is the number of fully loaded baseN * baseK blocks in L1 Buffer (B1).<br><br>Note: The value of this parameter must be greater than 0. |
| stepM, stepN, stepKa, stepKb<a name="p139009583566"></a> | int | stepM is the multiple of baseM in the buffer M direction of the left cube cached in L1 Buffer (A1).<br><br>stepN is the multiple of baseN in the buffer N direction of the right cube cached in L1 Buffer (B1).<br><br>stepKa is the multiple of baseK in the buffer Ka direction of the left cube cached in L1 Buffer (A1).<br><br>stepKb is the multiple of baseK in the buffer Kb direction of the right cube cached in L1 Buffer (B1).<br><br>Note: The value of this parameter must be greater than 0. |
| isBias<a name="p2051215216314"></a> | int | Whether to enable Bias. The parameter values are as follows:<br>0: Bias is not enabled (default value). 1: Bias is enabled.<br><br>Note: This parameter does not support values other than the above. If it is set to other values, the parameter behavior is undefined. |
| transLength<a name="p1620315053211"></a> | int | max(A1Length, B1Length, C1Length, BiasLength). A1Length, B1Length, C1Length, and BiasLength indicate the UB space size that cubes A/B/C/Bias need to temporarily occupy during computation, respectively. |
| iterateOrder | int | One Iterate computes a C cube tile of size [baseM, baseN]. After the Iterate is complete, Matmul automatically offsets the position of the C cube output by the next Iterate. iterOrder indicates the order of the automatic offset. The parameter values are as follows:<br>0: Offset in the M-axis direction first, and then in the N-axis direction. 1: Offset in the N-axis direction first, and then in the M-axis direction.<br><br>Note: This parameter does not support values other than the above. | dbL0A, dbL0B,<br><br>dbL0C | int | Whether MTE1 enables double buffer.<br><br>dbL0A: whether the left cube MTE1 enables double buffer. dbL0B: whether the right cube MTE1 enables double buffer. dbL0C: whether MMAD enables double buffer. If it is set to other values, the parameter behavior is undefined. |
| shareMode | int | This parameter is reserved. The developer does not need to pay attention to it. |
| shareL1Size | int | This parameter is reserved. The developer does not need to pay attention to it. |
| shareL0CSize | int | This parameter is reserved. The developer does not need to pay attention to it. |
| shareUbSize | int | This parameter is reserved. The developer does not need to pay attention to it. |
| batchM | int | This parameter is reserved. The developer does not need to pay attention to it. |
| batchN | int | This parameter is reserved. The developer does not need to pay attention to it. |
| singleBatchM | int | This parameter is reserved. The developer does not need to pay attention to it. |
| singleBatchN | int | This parameter is reserved. The developer does not need to pay attention to it. |
| mxTypePara | int | A combined parameter used in the MxMatmul scenario. It indicates the multiple of the size of scaleA/scaleB loaded into L1 relative to the size of cubes A/B loaded into L1. Details are as follows:<br>Bits 0 to 6 indicate the scale factor of the data volume loaded in the K direction between scaleA and cube A, scaleFactorKa, that is, scaleFactorKa = data volume of scaleA loaded in the K direction / data volume of cube A loaded in the K direction, with a data range of [1, 127].<br>Bits 8 to 14 indicate the scale factor of the data volume loaded in the K direction between scaleB and cube B, scaleFactorKb, that is, scaleFactorKb = data volume of scaleB loaded in the K direction / data volume of cube B loaded in the K direction, with a data range of [1, 127].<br>Bits 16 to 22 indicate the scale factor of the data volume loaded in the M direction between scaleA and cube A, scaleFactorM, that is, scaleFactorM = data volume of scaleA loaded in the M direction / data volume of cube A loaded in the M direction, with a data range of [1, 127].<br>Bits 24 to 30 indicate the scale factor of the data volume loaded in the N direction between scaleB and cube B, scaleFactorN, that is, scaleFactorN = data volume of scaleB loaded in the N direction / data volume of cube B loaded in the N direction, with a data range of [1, 127].<br><br>Note:<br>For the scaleA cube, multi-fold loading in the M direction is supported only when the Ka direction is fully loaded. That is, scaleFactorM can be set to a value greater than 1 only when baseK * stepKa * scaleFactorKa >= singleCoreK.<br>For the scaleB cube, multi-fold loading in the N direction is supported only when the Kb direction is fully loaded. That is, scaleFactorN can be set to a value greater than 1 only when baseK * stepKb * scaleFactorKb >= singleCoreK.<br>The data volume loaded in the M, N, and K directions for scaleA and scaleB cannot exceed the actual size.<br>This parameter takes effect only in the MDL template. |

In most cases, users obtain the TCubeTiling structure by calling the [GetTiling](GetTiling.md) API. For details, see [Usage Instructions](Matmul_Tiling_usage.md). If users customize the TCubeTiling parameters, the value of each parameter must satisfy the corresponding parameter constraints in [Table 1](#tcubetiling-struct) and [Table 2](#table1275812182115). If users need to modify and adjust the Tiling after obtaining the TCubeTiling structure by calling the [GetTiling](GetTiling.md) API, set the parameters by referring to the following TCubeTiling parameter constraints and recommended values for performance tuning.

-   TCubeTiling parameter constraints

    A set of valid TCubeTiling parameters must satisfy all constraints in [Table 2](#table1275812182115) simultaneously. If the MatmulConfig template of the Matmul object is the [MDL template](../Matmul_Kernel/MatmulConfig.md#template-features), in addition to [Table 2](#table1275812182115), the parameters must also satisfy [Table 3 MDL template supplementary constraints](#table1094616401179).

    **Table 2**  TCubeTiling constraints

    <a name="table1275812182115"></a>

    | Constraint | Description |
    | --- | --- |
    | usedCoreNum <= aiCoreCnt | The number of used cores is less than or equal to the maximum number of cores of the current AI processor. |
    | baseM * baseK * sizeof(A_type) * dbL0A< l0a_size | The base block of cube A does not exceed the l0a buffer size. |
    | baseN * baseK * sizeof(B_type) * dbL0B < l0b_size | The base block of cube B does not exceed the l0b buffer size. |
    | baseM * baseN * sizeof(l0c_type) * dbL0C < l0c_size, where l0c_type is the int32_t or float data type. | The base block of cube C does not exceed the l0c buffer size. |
    | baseN * sizeof(Bias_type) < biasT_size | The base block of Bias does not exceed the BiasTable buffer size. |
    | stepM * stepKa * db = depthA1<br>    <br>Here db indicates whether double buffer is enabled for the left cube MTE2, that is, whether double buffer is enabled for L1, with a value of 1 (double buffer not enabled) or 2 (double buffer enabled). | The value of depthA1 is the same as stepM * stepKa * db. |
    | stepN * stepKb * db = depthB1<br>    <br>Here db indicates whether double buffer is enabled for the right cube MTE2, that is, whether double buffer is enabled for L1, with a value of 1 (double buffer not enabled) or 2 (double buffer enabled). | The value of depthB1 is the same as stepN * stepKb * db. |
    | The cache block size AL1Size of cube A on L1 and the cache block size BL1Size of cube B on L1 must satisfy:<br>    Without bias: AL1Size + BL1Size <= L1_size<br>    <br>    With bias: AL1Size + BL1Size + baseN * sizeof(Bias_type) <= L1_size<br>    <br>    AL1Size and BL1Size are calculated as follows:<br>Transposed scenario:<br>AL1Size = CeilDiv(baseM, C0_size) * baseK * depthA1 * sizeof(A_type)<br>   BL1Size = baseN * baseK * depthB1 * sizeof(B_type)<br><br>    Non-transposed scenario:<br>AL1Size = baseM * baseK * depthA1 * sizeof(A_type)<br> BL1Size = CeilDiv(baseN, C0_size)* baseK * depthB1 * sizeof(B_type) | The cache blocks of cube A, cube B, and Bias on L1 satisfy the L1 buffer size limit.<br>    <br>Note: C0_size is 8 for the float data type, 16 for the half/bfloat16_t data type, 32 for the int8_t/fp8_e4m3fn_t/fp8_e5m2_t/hifloat8_t data type, and 64 for the int4b_t/fp4x2_e2m1_t/fp4x2_e1m2_t data type. |
    | baseM * baseK, baseK * baseN, and baseM * baseN are aligned in according to the NZ fractal format. | The base blocks of cube A, cube B, and cube C must satisfy the alignment constraints:<br>    baseM and baseN must be aligned to 16 elements. In the scenario where cube A is non-transposed and cube B is transposed, baseK must be aligned to C0_size. In other scenarios (cube A transposed or cube B non-transposed), baseK is aligned to 16 elements.<br>    <br>Note: C0_size is 8 for the float/int32_t data type, 16 for the half/bfloat16_t data type, 32 for the int8_t/fp8_e4m3fn_t/fp8_e5m2_t/hifloat8_t data type, and 64 for the int4b_t/fp4x2_e2m1_t/fp4x2_e1m2_t data type. |
    | In the MxMatmul scenario, if the positions of cubes A and B are both GM, there is no special restriction on singleCoreK. In this case, if the K-direction size of scaleA and scaleB (that is, Ceil(singleCoreK, 32)) is odd, the user must pad zeros in the K direction of scaleA and scaleB to an even number. For other combinations of the logical positions of cubes A and B, that is, when the positions of cubes A and B are not both GM, the value of singleCoreK aligned upward to 32 elements must be an even multiple of 32.<br>    <br>When the input data type is fp4x2_e2m1_t/fp4x2_e1m2_t, the inner axis must be even. | The data type of scaleA/scaleB is fp8_e8m0_t, and the K direction must be 2-byte contiguous. The K direction of scaleA/scaleB is 1/32 of the K of cubes A/B. When the positions of cubes A and B are not both GM, the value of singleCoreK aligned upward to 32 elements must be an even multiple of 32.<br>    <br>In the MxMatmul scenario, when the input data type is fp4x2_e2m1_t/fp4x2_e1m2_t, the minimum unit for computation is 8 bytes, and two 4-byte elements must be combined into one 8-byte unit for computation, so the inner axis must be even. |

    | Constraint | Description |

-   Recommended values for performance tuning

    Based on tiling tuning experience, some TCubeTiling parameter values or value selection methods are recommended as follows:

    -   Recommended base block \(baseM, baseN, baseK\): \(128, 256, 64\)
    -   dbL0A / dbL0B = 2
    -   depthA1 / \(stepM \* stepKa\) = 2
    -   depthB1 / \(stepN \* stepKb\) = 2
    -   Set the **stepKa**/**stepKb** parameters first so that the K direction is fully loaded, and then consider full loading in the M or N direction.
